# পাথরঘাটা ডিজিটাল কমিউনিটি লিমিটেড
## Privacy Policy / গোপনীয়তা নীতি

**কার্যকর তারিখ:** ১ নভেম্বর ২০২৬  
**সর্বশেষ হালনাগাদ:** ১ নভেম্বর ২০২৬

এই Privacy Policy পাথরঘাটা ডিজিটাল কমিউনিটি লিমিটেড-এর “পাথরঘাটা ডিজিটাল কমিউনিটি” Native App (“অ্যাপ”, “আমরা”, “আমাদের”) ব্যবহার করার সময় আপনার তথ্য কীভাবে সংগ্রহ, ব্যবহার, সংরক্ষণ, প্রকাশ ও সুরক্ষিত করা হয় তা ব্যাখ্যা করে। অ্যাপ ব্যবহার, account তৈরি বা কোনো তথ্য জমা দেওয়ার আগে এই নীতিটি পড়ুন।

এই নীতিতে উল্লেখিত কিছু feature account, device, app version, admin configuration বা service availability-এর ওপর নির্ভর করতে পারে। কোনো feature আপনার build-এ সক্রিয় না থাকলে সেই feature-এর data processing প্রযোজ্য হবে না।

## ১. আমরা কোন তথ্য সংগ্রহ করি

### ১.১ Account ও authentication তথ্য

আপনি account তৈরি বা login করলে আমরা Firebase Authentication-এর মাধ্যমে account identifier এবং authentication-related তথ্য প্রক্রিয়া করতে পারি। Login method অনুযায়ী email address, phone number, display name, profile photo বা provider identifier পাওয়া যেতে পারে। Password আমরা plaintext হিসেবে সংরক্ষণ করি না।

### ১.২ Profile তথ্য

আপনি নিজে দিলে নাম, ডাকনাম, profile photo, cover photo, phone, email, ইউনিয়ন, গ্রাম, এলাকা, পেশা, bio, social link, website, verification-related তথ্য এবং membership-related তথ্য সংরক্ষিত হতে পারে। কোন তথ্য profile-এ দেখাবেন তা privacy settings-এর মাধ্যমে নিয়ন্ত্রণ করার চেষ্টা করা হয়।

Phone ও email গোপন রাখার setting চালু থাকলে তা সাধারণ profile viewer-এর কাছ থেকে গোপন রাখা হয়। Contact information-এর visibility account relationship, profile privacy, feature rules এবং admin moderation-এর ওপরও নির্ভর করতে পারে।

### ১.৩ Post, comment ও social interaction

আপনি post, photo, audio, poll, feeling, check-in, comment, reply, like, repost, save, report বা mute action করলে সংশ্লিষ্ট content, timestamp, author UID এবং interaction record সংরক্ষিত হতে পারে।

Post privacy option—যেমন public, friends বা only me—অনুযায়ী content দেখানোর চেষ্টা করা হয়। Public post-এর sanitized projection community feed-এ রাখা হতে পারে। Public content, profile name, profile photo বা public interaction অন্য ব্যবহারকারীদের কাছে দেখা যেতে পারে। কোনো post public করার আগে এতে phone number, private address, identity document বা অন্য সংবেদনশীল তথ্য না দেওয়ার দায়িত্ব আপনার।

### ১.৪ Messages ও chat media

আপনি অন্য সদস্যের সঙ্গে message বা chat ব্যবহার করলে message metadata, conversation membership, timestamps এবং আপনার পাঠানো media সংরক্ষিত হতে পারে। Chat media নিরাপত্তার জন্য encrypted বা protected flow ব্যবহার করতে পারে, কিন্তু কোনো internet-based system-কে সম্পূর্ণ ঝুঁকিমুক্ত বলা যায় না।

### ১.৫ Feedback, Missing Query ও অভিযোগ

আপনি feedback, Missing Query বা service complaint পাঠালে title, details, category, location/landmark, tracking information, timestamp, status, admin reply এবং প্রয়োজনে আপনার account identifier সংরক্ষিত হতে পারে। Complaint-এর ক্ষেত্রে আপনি anonymous option ব্যবহার করতে পারেন; তবে account-level technical record বা service processing-এর জন্য কিছু identifier থাকতে পারে।

Feedback ও Missing Query-এর history আপনি নিজে দেখতে পারবেন। Admin review, status update বা reply থাকলে তা একই history-তে দেখা যেতে পারে।

### ১.৬ রক্তদান ও জরুরি service তথ্য

রক্তদাতা বা রক্তের অনুরোধ feature ব্যবহার করলে blood group, service area, availability, প্রয়োজনের সময়, hospital/clinic, contact number এবং সংশ্লিষ্ট request information প্রক্রিয়া হতে পারে। Donor phone বা private contact সাধারণ public donor listing-এ দেখানোর জন্য নয়; তবে আপনি যে information দেন, feature-এর operational প্রয়োজন এবং admin handling অনুযায়ী তা process হতে পারে। রক্তের request, donor availability বা medical outcome-এর নিশ্চয়তা অ্যাপ দেয় না।

### ১.৭ Marketplace তথ্য

Marketplace ব্যবহার করলে product/shop information, cart, order, buyer/seller identifiers, delivery বা pickup preference, order status, delivery address/contact এবং Cash on Delivery বা pay-on-pickup সংক্রান্ত তথ্য প্রক্রিয়া হতে পারে। বর্তমান flow online payment gateway নয়; payment বা order fulfilment-এর বাস্তব দায় সংশ্লিষ্ট buyer ও seller-এর ওপর থাকে।

### ১.৮ Device ও technical information

অ্যাপ চালাতে Firebase, Expo/EAS এবং notification infrastructure-এর মাধ্যমে device/app version, push token, crash বা operational metadata, network request information এবং security-related event information প্রক্রিয়া হতে পারে। Push notification চালু করলে notification delivery-এর জন্য device push token এবং notification preference ব্যবহার করা হয়।

অ্যাপ কিছু feature-এ camera, photo library, microphone বা foreground location permission চাইতে পারে। আপনি permission না দিলে সংশ্লিষ্ট feature কাজ নাও করতে পারে। Location কেবল আপনার অনুমতি ও feature-এর প্রয়োজন অনুযায়ী ব্যবহার করার কথা; অভিযোগ বা service form-এ location manually-ও দেওয়া যায়।

## ২. Media ও third-party service

অ্যাপ Firebase Authentication, Firebase Realtime Database, Firebase Functions এবং Cloudinary-এর মতো third-party infrastructure ব্যবহার করতে পারে। Photo, audio বা অন্যান্য media upload হলে media provider-এর server-এ upload হতে পারে এবং media URL app record-এ সংরক্ষিত হতে পারে। Public post বা public profile-এর media public link-এর মাধ্যমে accessible হতে পারে।

Cloudinary upload বর্তমানে app-এর media flow-এর অংশ। Sensitive document, NID, private complaint evidence বা অন্যের confidential material upload করার আগে app-এর screen-এ দেওয়া নির্দেশনা মেনে চলুন। Secure signed upload ও private delivery সব media category-তে সমানভাবে সক্রিয় আছে—এমন নিশ্চয়তা এই document দিচ্ছে না।

Third-party provider-রা তাদের নিজস্ব privacy policy অনুযায়ী data process করতে পারে। তাদের policy-ও পড়ুন।

## ৩. আমরা তথ্য কীভাবে ব্যবহার করি

আমরা তথ্য ব্যবহার করতে পারি:

- account তৈরি, login, profile ও account security পরিচালনা করতে;
- community feed, friends, profile, post, comment, chat, notification ও search feature দিতে;
- post privacy, interaction authorization এবং abuse prevention কার্যকর করতে;
- feedback, Missing Query, complaint, blood request ও directory correction review করতে;
- marketplace order, seller/buyer coordination এবং status update পরিচালনা করতে;
- push notification পাঠাতে, যদি আপনি তা চালু রাখেন;
- app performance, reliability, security, cache, rate limit ও troubleshooting উন্নত করতে;
- spam, fraud, harassment, illegal content ও policy violation শনাক্ত/তদন্ত করতে;
- আইনগত বাধ্যবাধকতা, নিরাপত্তা বা জরুরি পরিস্থিতিতে প্রয়োজনীয় ব্যবস্থা নিতে;
- admin-configured update, policy, download link বা service notice দেখাতে।

আমরা আপনার private data public feed বা public profile-এ প্রয়োজনের অতিরিক্ত প্রকাশ না করার জন্য projection ও Firebase Rules ব্যবহার করি। তবে আপনি নিজে public content-এ কোনো private information লিখলে সেই disclosure-এর দায় আপনার।

## ৪. কখন তথ্য শেয়ার হতে পারে

আমরা তথ্য শেয়ার করতে পারি:

1. আপনার privacy choice অনুযায়ী অন্য app user-এর সঙ্গে—যেমন public profile, public post বা community interaction;
2. সংশ্লিষ্ট admin/moderator-এর সঙ্গে, feedback, complaint, verification, marketplace বা safety review-এর জন্য;
3. Firebase, Cloudinary, Expo notification এবং প্রয়োজনীয় service provider-এর সঙ্গে, feature চালানোর জন্য;
4. আইন, আদালত, সরকারি কর্তৃপক্ষ বা valid legal process মেনে চলতে;
5. abuse, fraud, security incident, physical safety বা অন্যের অধিকার রক্ষার প্রয়োজন হলে;
6. business transfer বা service reorganization হলে, প্রযোজ্য আইন ও notice-এর অধীনে।

আমরা personal information বিক্রি করার উদ্দেশ্যে সংগ্রহ করি না।

## ৫. Privacy settings ও আপনার নিয়ন্ত্রণ

Settings থেকে, feature availability সাপেক্ষে, আপনি:

- profile search visibility পরিবর্তন করতে;
- phone/email গোপন রাখতে;
- online status, read receipt, tag permission ও message privacy নিয়ন্ত্রণ করতে;
- post public, friends বা only me হিসেবে প্রকাশ করতে;
- push notification preference পরিবর্তন করতে;
- নিজের post edit বা delete করতে এবং কিছু ক্ষেত্রে Trash Bin থেকে restore করতে;
- feedback ও Missing Query history দেখতে;
- account deletion request করতে পারেন।

Privacy setting পরিবর্তন করার পর আগের public copy, screenshot, repost, cached content বা অন্য user-এর সংরক্ষিত copy সঙ্গে সঙ্গে মুছে যাবে—এমন নিশ্চয়তা দেওয়া যায় না।

## ৬. Data retention ও account deletion

Feature, legal requirement, dispute, safety investigation, backup, fraud prevention ও operational need অনুযায়ী data বিভিন্ন সময় সংরক্ষিত হতে পারে। Post delete করলে app-এর Trash Bin retention period-এ record থাকতে পারে; current implementation-এ নিজের deleted post-এর restore window সীমিত।

Account deletion চাইলে Settings-এর account deletion flow ব্যবহার করুন বা আমাদের legal contact-এ যোগাযোগ করুন। Verification, complaint, transaction, abuse investigation, legal record বা backup-এর কারণে কিছু data immediate deletion-এর পরিবর্তে সীমিত access-সহ retention period পর্যন্ত রাখা হতে পারে। Deletion সম্পন্ন হলে সাধারণত account access, profile, user content ও associated service access হারাবেন।

## ৭. Data security

আমরা Firebase Authentication, database security rules, user-scoped reads, public/private projection, bounded access এবং operational controls ব্যবহার করে data সুরক্ষিত রাখার চেষ্টা করি। কিন্তু password sharing, unsafe device, screenshot, public URL, phishing, unauthorized access, third-party provider failure বা internet transmission-এর কারণে সম্পূর্ণ নিরাপত্তার নিশ্চয়তা দেওয়া যায় না।

আপনার দায়িত্ব হলো শক্তিশালী password ব্যবহার করা, OTP/password কাউকে না দেওয়া, shared device থেকে logout করা এবং public post-এ sensitive information না দেওয়া।

## ৮. শিশুদের privacy

অভিভাবকের অনুমতি ছাড়া শিশুদের personal information, photo, contact বা identity document upload করবেন না। কোনো শিশুর তথ্য ভুলভাবে সংগ্রহ হয়েছে মনে হলে legal contact-এ জানান। প্রযোজ্য আইন অনুযায়ী আমরা তা review করার চেষ্টা করব।

## ৯. External links ও third-party content

অ্যাপে Facebook, website, map, Cloudinary media, download link, marketplace seller link বা অন্য external service থাকতে পারে। External site বা service-এর content, security ও privacy practice আমাদের নিয়ন্ত্রণে নাও থাকতে পারে। Link খোলার আগে সতর্ক থাকুন এবং তাদের policy পড়ুন।

## ১০. এই নীতির পরিবর্তন

Feature, law, provider বা data practice পরিবর্তিত হলে আমরা এই policy update করতে পারি। নতুন version-এর কার্যকর তারিখ উপরে দেওয়া থাকবে। গুরুত্বপূর্ণ পরিবর্তন হলে app notice, Settings link বা অন্য উপযুক্ত মাধ্যমে জানানো হতে পারে।
